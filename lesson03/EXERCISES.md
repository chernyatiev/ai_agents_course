# Занятие 3. Упражнения

## На закрепление
1. Вызовите в `lesson02` функцию `python_eval` с выражением
   `[c.__name__ for c in ().__class__.__base__.__subclasses__() if c.__name__ == 'Popen']`
   (через `uv run python -c ...`). Затем проверьте ту же строку в `lesson03` через
   `permissions.evaluate("python_eval", {"expression": ...})`. На каких воротах она
   остановлена? Найдите соответствующий тест.
2. Попросите агента посчитать задачу перебором через `python_run` и ответьте `N`.
   Что модель сделала после отказа? Поменяйте формулировку в `SYSTEM_PROMPT` так,
   чтобы после отказа она предлагала решение через `z3_check`.
3. **Обход ворот 1.** Скрипт ниже проходит AST-проверку:
   ```python
   from sympy import sympify
   u = chr(95) * 2
   print(sympify(u + "import" + u + "('os').getcwd()"))
   ```
   Почему? Что его останавливает на самом деле? Почему поэтому `python_run` должен
   спрашивать всегда, а не только «когда что-то подозрительно»? Предложите и
   реализуйте исправление (подсказка: `chr`, `sympify`, `parse_expr`, `lambdify`).
4. Добавьте правило в `RULES`: спрашивать, если в скрипте `python_run` больше
   30 строк. Напишите тест. Убедитесь, что `loop.py` не изменился.
5. Сравните время `python_eval("2+2")` в `lesson02` и `lesson03`
   (`time uv run python -c ...`). Откуда разница? Где разумно держать границу
   «в процессе / в песочнице»?
6. Модель передала `"timeout": 60`. Что произошло: отказ разрешений или ошибка
   инструмента? Где правильнее проверять такие аргументы?

## Перенеси на свой агент
1. Составьте таблицу своих инструментов: что **запрещено всегда**, что **требует
   подтверждения**, что **разрешено**. Добавьте её в `SPEC.md` (раздел «Модель
   безопасности»).
2. Опишите для каждого инструмента худший сценарий: что сделает модель, если
   ошибётся или её «уговорят» через данные (prompt injection).
3. Реализуйте `permissions.check` хотя бы с одним правилом deny и одним правилом ask.
   Функцию `ask` передавайте параметром и подменяйте в тестах.
4. Если ваш агент выполняет код или долгие вычисления, оберните их в отдельный процесс
   с таймаутом.

Критерий готовности: опасный вызов не выполняется без решения человека, зависший
инструмент не роняет REPL, отказ доходит до модели текстом, и всё это проверено
тестами без сети.
