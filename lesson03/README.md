# Занятие 3. Песочница и разрешения

Референс: [s03 — Permission](https://learn.shareai.run/en/s03/)

**Проверять разрешения нужно до выполнения.** Цикл из занятия 2 сохранён целиком,
в него добавлена одна проверка перед `tools.call`:

```python
for call in reply.tool_calls:
    decision = permissions.check(call.name, call.arguments, ask=ask)   # ← новое
    if decision.allowed:
        result = tools.call(call.name, call.arguments)                  # внутри — песочница
    else:
        result = f"Отказано: {decision.reason}"                          # модель видит отказ
    messages.append(tool_result(call.id, result))
```

У занятия два слоя, их важно не путать:

| Слой | Вопрос | Файл |
| --- | --- | --- |
| **Разрешения** | *Можно ли* выполнять этот вызов? | `permissions.py` |
| **Песочница** | *Что может натворить* уже разрешённый вызов? | `sandbox.py` |

Безопасность нельзя строить на доверии к модели: строка «не используй import»
в системном промпте ничего не гарантирует. Ограничения задаёт код harness.

## Зачем это нужно: lesson02 ломается одной строкой

```python
python_eval("[c.__name__ for c in ().__class__.__base__.__subclasses__() if c.__name__=='Popen']")
# lesson02 → ['Popen']   пустой __builtins__ не спасает: через кортеж виден весь интерпретатор
python_eval("sum(range(10**12))")
# lesson02 → REPL висит, таймаута нет
```

Та же дыра есть в `z3_check` (`eval` ограничений) и в SymPy (`parse_expr` внутри вызывает `eval`).

## Конвейер разрешений: три ворот

| Ворота | Что проверяется | Совпало → |
| --- | --- | --- |
| 1. **Deny** | Код в аргументах разбирается в **AST**: `__dunder__`, `getattr/eval/exec/open/...`, строки с `__`, import не из белого списка | отказ, пользователя не спрашиваем |
| 2. **Rules** | `python_run` (любой скрипт), таймаут > 5 с, целая константа > 10⁷ (большой перебор) | передаём в ворота 3 |
| 3. **Ask** | `Разрешить? [y/N/a]` (`a` — «всегда для этого инструмента до конца сессии») | allow / deny |

Если ни одни ворота не сработали, вызов выполняется сразу. Так проходит большинство
вызовов: `sympy_solve`, `z3_check`, короткий `python_eval`.

**Почему AST, а не подстроки.** В референсе запреты сделаны поиском подстроки
(`"rm -rf /" in command`), и там же честно сказано, что это ненадёжно. Мы делаем шаг
вперёд: `ast.parse` и обход узлов. Это тоже не граница безопасности (см. упражнения),
но обойти такую проверку гораздо труднее. Обход всё же есть: скрипт может собрать
строку с `__` через `chr(95)` и отдать её в `sympy.sympify`, который внутри вызывает
`eval` (упражнение 3). Поэтому `python_run` спрашивает **всегда**: последняя линия
обороны — человек, а за ним песочница.

Режимы (`--mode` или `/mode`) влияют только на ворота 3:

| Режим | Ворота 3 | Аналог в Claude Code |
| --- | --- | --- |
| `default` | спросить пользователя | default |
| `auto` | разрешить без вопроса | bypassPermissions |
| `strict` | отказать без вопроса | plan / dontAsk |

Ворота 1 действуют в любом режиме, в том числе после ответа `a`.

## Песочница

- `sandbox.run_isolated(func, kwargs, timeout)` вызывает функцию инструмента в отдельном
  процессе (`multiprocessing`, метод `spawn`). Его используют `python_eval` (5 с),
  `sympy_*` (15 с) и `z3_check` (30 с). Таймаут задаётся при регистрации:
  `register(..., timeout=5)`. Ошибка внутри приходит с тем же типом (`ZeroDivisionError`, ...).
- `sandbox.run_python(code, timeout)` — новый инструмент `python_run`: `python -I`,
  пустое окружение (ключ API из `.env` не виден), временная пустая папка,
  вывод обрезается до 4000 символов.
- Лимиты ОС через `resource.setrlimit` (только POSIX): процессорное время, размер файлов
  (1 МБ), память (1 ГБ, **в macOS не работает** — ОС не даёт ограничить `RLIMIT_AS`).
  В Windows остаётся только таймаут.

> Это учебная песочница. Дочерний процесс работает с правами пользователя и видит
> файловую систему. Настоящая изоляция — контейнер, nsjail/gVisor, отдельная ВМ.

## Новый инструмент `python_run`

Многострочный скрипт для перебора: циклы, функции, `itertools`. Это первый инструмент
курса, который по-настоящему опасен, поэтому каждый его запуск подтверждает пользователь.

## Запуск

```bash
cd lesson03
cp ../lesson02/.env .env      # или cp .env.example .env и заполнить
uv run agent -v               # default: спрашивать
uv run agent --mode auto      # не спрашивать (ворота 1 всё равно работают)
uv run agent --mode strict    # отказывать без вопроса
uv run --group dev pytest     # 78 тестов, сеть не нужна (~25 с: процессы и таймауты)
```

Команды REPL: `/tools`, `/permissions`, `/mode <режим>`, `/messages`, `/reset`, `/exit`.

## Демо

1. **Скрипт с подтверждением.** «Сколько шестизначных чисел, у которых сумма первых трёх
   цифр равна сумме последних трёх? Проверь перебором скриптом.» Модель вызывает
   `python_run`, появляется `⚠ Запуск скрипта Python`, отвечаем `y` и получаем **50412**.
2. **Отказ.** То же самое, но ответить `N`. Модель получает `Отказано: пользователь
   отклонил вызов`, переходит на `python_eval` и получает тот же ответ 50412.
3. **Режимы.** Задача из демо 1 в `--mode auto` выполняется через `python_run` без вопроса.
   В `--mode strict` модель получает отказ и считает через `python_eval`.
4. **Таймаут.** Зависшее вычисление не роняет агента:
   ```bash
   uv run python -c "from agent import tools; print(tools.call('python_eval', '{\"expression\": \"sum(range(10**12))\"}'))"
   ```
   Через 5 с: `Ошибка TimeoutError: превышен лимит времени 5 с, вычисление остановлено`.
5. **Обход ограничений.** Проверка запрета показывается тестами:
   `uv run --group dev pytest -k denied -v`.

## Известные ограничения (задел на следующие занятия)

- Проверка разрешений вписана прямо в цикл. Логирование, аудит, автокоммит придётся
  добавлять туда же → хуки вокруг цикла (s04 Hooks).
- Ответ «всегда» хранится только в памяти процесса. Постоянные правила (файл настроек)
  понадобятся, когда появится запись на диск → **занятие 4**, банк задач: `save_problem`
  станет первым инструментом с правилом «запись вне `bank/` → спросить».
- Модель сама формализует задачу и сама проверяет → **занятие 5**, независимый проверяющий.
- Нет лимита шагов цикла: модель может бесконечно получать «Отказано» → **занятие 8**.
- `run_isolated` запускает дочерние процессы методом `spawn`, а он заново импортирует
  главный модуль. Если вызываете `run_turn` из своего скрипта, оберните запуск в
  `if __name__ == "__main__":`. Без этого каждый дочерний процесс выполнит скрипт заново,
  и все вызовы `python_eval`, SymPy и z3 будут завершаться по таймауту.
